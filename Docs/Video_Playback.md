# Видеоролики: варианты декодирования для Linux-порта

## Исходные данные

- PC-ресурсы: ролики в `Content/Videos/*.wmv` — контейнер ASF, видео WMV9
  (VC-1), звук WMA. Примеры: `Intro.wmv`, `atari.wmv`, `Universal_ntsc.wmv`,
  `Eyeshine.wmv` (эффект «глаза Риддика» может быть видео-текстурой!).
- В движке ЕСТЬ готовый видеоплеер-текстура: `CTextureContainer_Video_Theora`
  (`MSystem/Raster/MTextureContainerTheora.cpp`, собирается уже сейчас) —
  декодирует **Ogg/Theora** через API libtheora, звук ролика гонит в
  `SYSTEM.SOUND` (микшер). Ворнинг при старте
  `Could not create CTextureContainer_Video_Theora` — классу не хватает
  зарегистрированной реализации/библиотеки libtheora (в SDK дерева её нет,
  есть только ogg+vorbis).
- Win32-обёртки Bink/XMV из дерева исключены (нет либ), PS3 использовал свои
  форматы.

## Варианты

### A. libtheora + офлайн-конвертация роликов (РЕКОМЕНДУЕТСЯ)
- Подключить **libtheora** (системная `libtheora-dev` или вендорить в
  `Source/P5/SDK/Theora/` — ~40 файлов C, лицензия BSD, собранный размер
  ~300–400 КБ; ogg уже в дереве).
- Достроить/зарегистрировать `CTextureContainer_Video_Theora` (код плеера уже
  написан Starbreeze — нужно только слинковать и убрать причину ворнинга).
- Ролики один раз конвертируются на машине разработчика:
  `ffmpeg -i Intro.wmv -c:v libtheora -q:v 7 -c:a libvorbis Intro.ogv`
  (скрипт на все файлы; кладутся рядом, сканер видео подхватывает).
- Плюсы: почти нулевой новый код, крошечная зависимость, играет через штатный
  путь движка (видео-текстуры работают и в мире, не только фулскрин).
- Минусы: требуется шаг конвертации ресурсов у пользователя.

### B. ffmpeg (libavformat + libavcodec + libswscale)
- Прямое проигрывание `.wmv` без конвертации. Новый контейнер-класс
  `CTextureContainer_Video_FFmpeg` по образцу Theora-класса (тот же интерфейс:
  декодировать кадр → YUV→RGB → залить в текстуру; звук → микшер).
- Жирность лечится кастомной сборкой:
  `./configure --disable-everything --enable-demuxer=asf
  --enable-decoder=wmv3,vc1,wmav2 --enable-protocol=file
  --disable-programs --disable-network ...` → ~2–4 МБ статически.
  Либо системные so (на десктопе ffmpeg обычно есть; на ARM-таргетах хуже).
- Плюсы: оригинальные файлы как есть. Минусы: заметная зависимость, новый
  класс-плеер (~500–800 строк), лицензия LGPL (динамическая линковка).

### C. Лёгкие библиотеки — почему НЕ подходят
- `pl_mpeg` (single-header) — только MPEG-1/MP2: пришлось бы конвертировать,
  тогда уж лучше Theora (вариант A, плеер уже в движке).
- `libvlc`, `gstreamer` — тяжелее ffmpeg по рантайм-зависимостям.
- Отдельного открытого декодера VC-1/WMV9 вне ffmpeg практически нет.

## Решение

Порядок работ: сейчас ролики просто пропускаются (не блокер). Когда дойдём —
делаем **A** (libtheora + скрипт конвертации), т.к. плеер уже написан в движке;
**B** держим как опцию «из коробки» для десктопа, если конвертация окажется
неудобной пользователям.

Заметка: звук ролика идёт через `SYSTEM.SOUND` — сначала нужен звуковой бэкенд
(см. `Docs/Sound_SDL2.md`), иначе видео будет немым/может не тикать по таймингу
аудио-дорожки.
