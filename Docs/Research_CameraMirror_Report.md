# Отчёт: настоящая причина «зеркала камеры» и судьба костыля W2V.X

По спеке `Docs/Research_CameraMirror.md` (форма §7). Ветка `riddick-render`,
постановка — `55844be`. Метод: 6 параллельных исследований по коду +
git-истории; игра не собиралась и не запускалась.

---

## 1. Ответ на §3: настоящая причина и правильное место исправления

**Рассогласования хиральности между движком и GLES3-портом не существует.**
Трансформ-цепочка порта поэлементно идентична PC-ретейлу (RndrGL) и
PS3GCM — доказано статически по каждому звену (§2). Камера и ввод
платформенно-нейтральны. Следовательно:

- **Правильное одноточечное исправление — УДАЛЕНИЕ костыля**
  (`XREngine.cpp:1053-1075`, негирование столбца 0 `m_W2VMat`/`m_dW2VMat`),
  а не перенос флипа в другое место: исправлять нечего, флип не нужен
  вообще. Точка единственная, и она закрывает всех потребителей разом
  (GPU, CPU-культинг, scissor, texgen) — они все читают `m_W2VMat` или её
  производные (реестр — §3).
- «Зеркало X» 2026-07-22/23 — **композитное наблюдение в конфаундированной
  конфигурации**, а не дефект трансформации:
  - 2026-07-22 09:35 (`7f247c7`) cull-маппинг был ИНВЕРТИРОВАН
    (`CULLCW → glCullFace(GL_FRONT)`); исправлен на retail только в 19:14
    (`c9d6e2d`). «Подтверждение зеркала» (`264afde`, MIRROR_X) сделано в
    16:24 — **пока мир рендерился наизнанку** (hollow-mask эффект: видишь
    внутренности дальней стены, параллакс едет в противоход — субъективно
    это и есть «зеркальный мир» и «LEFT двигает вправо»).
  - Тем же вечером был инвертирован pitch мыши (PS3-ветка, тоже `c9d6e2d`).
  - «Геометрия перед камерой отсекается как сзади» (обоснование `d472fa0`)
    на CPU-стороне **невозможно от X-зеркала в принципе** (§2.5): все
    facing-тесты BSP2 инвариантны к знаку столбца 0. Симптом относился к
    GPU-культингу (тот самый инвертированный маппинг) и/или к отсутствию
    PVS («huge slowdown on empty scenes» — `[BSP2] PVS entries: 0`,
    WBSP2Loader.cpp:2555-2567, с камерой не связано).
- Поскольку статическое доказательство полное, но наблюдение 2026-07-22
  было эмпирическим, финальное подтверждение — один A/B-прогон с
  `RIDDICK_NO_CAMFLIP=1` (§6). Предсказание: мир без костыля рендерится
  как в retail — НЕ зеркально, skybox совпадает с миром, winding корректен
  при дефолтном `RIDDICK_CULL_MODE=0`.

**Чёрная полоса / scissor-полоса — отдельный дефект, не хиральность.**
CPU-проекция (`CalcBoxScissor`) и GPU-путь используют ОДНУ матрицу
(`m_VPVMat = pVC->m_W2VMat`, WBSP2Portal.cpp:1335 ← XREngine.cpp:1691) и
формально эквивалентные формулы (при полном вьюпорте и `ox=0` —
тождественные, §2.6). Зеркалирование rect'а (`RIDDICK_SCISSOR_MIRRORX`)
не могло починить полосу и не починило: rect не «в чужой хиральности», а
считается из других входных данных (боксы света) или в другом контексте.
Локализуется дампом `RIDDICK_DBG_SCISSOR` (§5).

## 2. Доказательства (по звеньям цепочки)

### 2.1 Проекция движка — `MSystem/Raster/MRender.cpp:441-444`

```
row0 = ( +xScale/2,         0,               0, 0 )
row1 = (        0,  -yScale/2,               0, 0 )
row2 = (     ox/2,      oy/2,   Far/(Far-Near), 1 )
row3 = (        0,          0, -Near*Far/(...), 0 )
```

- `w_clip = z_view` (камера смотрит в +z), `z_ndc ∈ [0,1]` (D3D-диапазон);
- **x не негируется**: x_v>0 → право; **y негируется один раз** (k[1][1]<0,
  запечённый флип под экранную y-down конвенцию движка) → det(3x3) < 0;
- строится без единого `#ifdef PLATFORM_*` — одинакова на PC/PS3/Linux.

### 2.2 GLES3-бэкенд ≡ retail, поэлементно

- `Viewport_Update` (MDisplaySDL2.cpp:4550-4597): те же `GetProjectionMatrix()`
  + масштаб столбцов 0/1 на **положительные** `2/W`, `2/H`;
  `glViewport(R.p0.x, ScreenH()-R.p1.y, W, H)` — трансляция Y, как retail.
- RndrGL (PC-ретейл, декомпайл): `glViewport(x, H-y1, w, h)` (:37311),
  проекция `row0 *= 2/w; row1 *= 2/h; glLoadMatrixf` (:37317-37328),
  модель `glLoadMatrixf` напрямую (:76164-76176). `glScale*` — **ноль
  вхождений в DLL**; `glDepthRange` — ноль вхождений.
- PS3GCM: то же масштабирование строк проекции (MRenderPS3_Context.cpp:
  283-286) + `Transpose`; единственная знаковая операция бэкенда —
  `gcmSetViewport scale[1] = -h/2` (:267-272).
- Upload: `glUniformMatrix4fv(..., GL_FALSE, ...)` (GLES3_Shader.cpp:140)
  на row-major памяти → GLSL видит Mᵀ → `uMVP * vec4(v,1)` ≡ движковому
  `v·M` (строковая конвенция подтверждена: MMath.h:3955-3961, :2645-2649;
  Multiply — :1387-1397; трансляция в строке 3 — :52, :895).
- Z-ремап `gl_Position.z = 2z - w` во всех 6 программах (MDisplaySDL2.cpp:
  174, 373, 495, 712, 828, 1068) — компенсация z∈[0,w]→[-w,w]; **манипуляций
  со знаком x/y в gl_Position нет ни в одном шейдере**.
- Композит FBO→окно при `uRot=0` тождественен (:1217-1229, :2098-2153).
- Cull: retail-маппинг `glFrontFace(GL_CCW)` + `CULLCW→GL_BACK`
  (MDisplaySDL2.cpp:4291-4317, дефолт RIDDICK_CULL_MODE=0) = RndrGL
  (:38438-38439, :77659-77666: флаг 0x1000 → GL_BACK) = PS3
  (MRenderPS3_Attrib.cpp:288-294).

**Итог: в GLES3-бэкенде нет ни одного негирования X. Единственное
X-преобразование во всём пайплайне — сам костыль (XREngine.cpp:1064-1073).**

### 2.3 Камера и ввод платформенно-нейтральны

Цепочка: `MInput_SDL2.cpp:295-303` (xrel/yrel сырые, RotateDelta при
rotate=0 — passthrough) → `Con_Look` (WClientMod.cpp:2306-2336:
`dLook[2] = +dx·sens` — yaw никогда не негировался) →
`m_Control_Look_Wanted` → `CreateMatrixFromAngles(0,…)`
(WObj_CharCamera.cpp:1099-1100, MMath.h:3239-3302 — чистый скалярный
шаблон без `#ifdef`) → `Render_GetCamera` → `Engine_BuildViewContext` →
`ViewContextImpl::Clear`. Все `#ifdef PLATFORM_*` на пути выпиливаны или
Linux идёт общей веткой с Win/PS3. Прецедент с pitch (инверсия Y в не-Win
ветке) аналога по X **не имеет**.

### 2.4 BSP2: данные и facing-тесты чистые

- Плоскости/вершины читаются raw + byte-swap (WBSP2Loader.cpp:2232-2244) —
  «инвертированных нормалей BSP» в коде нет и в git-истории не было.
- Per-face CPU-backface-cult выключен компиляционно
  (`//#define MODEL_BSP_BACKFACECULL`, WBSP2Model.cpp:50); видимость =
  PVS + клип-объёмы + боксы.
- `CRC_ClipVolume::CopyAndTransform` (MRender.cpp:291-329) корректен для
  ортогональных матриц (прямой трансформ плоскостей = inverse-transpose
  для ортогонального случая), mirrored-ветка сохраняет инвариант
  «inside = отрицательная сторона». Двойной инверсии нет.

### 2.5 Костыль не влияет ни на один CPU-тест видимости (выкладка)

Костыль: `W2V' = W2V·S`, `S = diag(-1,1,1,1)`. Тогда
`m_CurVMatInv = S·V2W·WInv` (WBSP2Portal.cpp:1272):

- `m_CurLocalVP = GetRow(m_CurVMatInv, 3)` (:1300): левое умножение на S
  негирует СТРОКУ 0; строка 3 (позиция камеры) **не меняется** → все тесты
  `plane.Distance(CurLocalVP)` (порталы :209-211, обход :754-766, дети
  :785/:802) инвариантны к костылю.
- View-фрустум X-симметричен (MRender.cpp:451-470, 609-619) →
  `m_CurClipVolume` (:1297-1298) под костылём — тот же набор плоскостей.
- `m_ClipW` строится из `_CameraWMat` (XREngine.cpp:2604, 2651), а не из
  `m_W2VMat` — инвариантен.
- `MACRO_ISMIRRORED(m_CurVMatInv)` (:491) с костылём всегда true — и это
  **согласованная** ветка (det реально < 0): порядок вершин портального
  квада соответствует фактической хиральности. После снятия костыля вернёт
  корректное false. Поведение не меняется ни в одном варианте.

Вывод: «front-of-camera culled as behind» через BSP не объясняется и
костылём не чинился — чинился GPU-winding (det-флип меняет, какие грани
культит GL) в период, когда cull-маппинг путали (4 смены за 2 дня:
`7f247c7` → `c9d6e2d` → `d582b37`(GL_CW) → `74cd06d` → `76a79ab`).

### 2.6 CPU-scissor ≡ GPU-рендер (формулы)

GPU: x_win = x_v·xScale/(2z) + W/2 (колонка 0 · 2/W в Viewport_Update +
glViewport). CPU: `x_scr = (x_v/z)·(xScale/2) + VPMid.x`
(WBSP2Portal.cpp:169, :1330; WTriMesh.cpp:1045-1062). При полном
вьюпорте (`vp_x=0`, `VPMid.x=W/2`) и `ox=0` — **тождественны**. Обе
стороны читают одну (флипнутую) W2V → зеркальность rect'ов относительно
кадра исключена; это подтверждает и неудачу `SCISSOR_MIRRORX`. Расхождение
возможно только во входных данных (боксы света, иной `_VMat` на момент
View_Init) или в не-полном вьюпорте (ox≠0, `m_Rect`≠`m_Clip.clip`) —
проверяется дампом.

## 3. Что сломается при снятии костыля — и что починится

Полный реестр потребителей `m_W2VMat`/`m_dW2VMat` (точка записи одна —
`Clear`, XREngine.cpp:1033/1038):

| Потребитель | Эффект снятия |
|---|---|
| GPU-путь (L2V → `m_ModelMat` → MVP, XREngine.cpp:3119, MDisplaySDL2.cpp:5471) | Кадр возвращается в состояние «как retail». **Предсказание: не зеркальный.** |
| Winding на GPU | det цепочки снова = retail → дефолтный `RIDDICK_CULL_MODE=0` корректен. NB: **сейчас** (костыль + retail-маппинг) det флипнут → математически культятся противоположные грани (inside-out); ушло из виду на фоне сломанного освещения. Проверяется прогоном §6. |
| Skybox (WSky.cpp:592-597 заново инвертирует `m_CameraWMat`, минуя `m_W2VMat`) | **Чинится автоматически**: небо — единственный потребитель в нефлипнутой хиральности, поэтому и инвертировано. |
| BSP2-культинг (порталы, фрустум, PVS, `m_CurLocalVP`) | Не меняется (инвариантность доказана §2.5). |
| `m_bIsMirrored` (XREngine.cpp:1051) | Спец-расчёт «до флипа» можно упростить (считать на финальной матрице — ответ тот же, false для обычной камеры). Оставить как есть — тоже корректно. |
| `MACRO_ISMIRRORED(m_CurVMatInv)` (WBSP2Portal.cpp:491) | Возвращается к честному false; ветка остаётся согласованной (§2.5). |
| `m_CurViewVP` для specular/env (WTriMesh.cpp:5364-5366, WBSP2Model.cpp:5121) | Сейчас X-флипнут (латентный дефект) — **чинится**. |
| Fog texgen `VFwd` (WBSP2Model.cpp:1940, WTriMesh.cpp:2355) | X-компонента нормали сейчас флипнута — чинится (латентно, FP20). |
| `CalcBoxScissor` (WTriMesh.cpp:1019, WBSP2Portal.cpp:115, WBSP4Glass.cpp:1679) | Rects остаются согласованными с GPU (формулы тождественны, §2.6). Полоса — отдельный дефект, см. §5-§6. |
| Portal screen-projection texgen (XREngine.cpp:3224) | Консистентен с GPU при любом варианте. |
| `m_dW2VMat` → motion map (XRShader.cpp:2007/2216) | Латентно (FP20DEF не реализован); флип применён к ней же — консистентна. |
| Debug-текст/billboards (XRUtil.cpp:91-95) | Сейчас зеркалятся — чинятся. |
| Компенсации, снимаемые вместе с костылём | `RIDDICK_SCISSOR_MIRRORX` (MDisplaySDL2.cpp:4385) — удалить; `RIDDICK_CULL_MODE` — оставить дефолт 0; комментарий про GL_CW в XREngine.cpp:1060-1062 — устарел (дефолт CCW). |

**Итого: при снятии костыля НИЧТО не ломается; чинятся skybox,
spec/env-векторы, fog-нормали, debug-текст и (вероятно) winding мира.**

## 4. Опровергнутые гипотезы §5 спеки

1. **«Знак X в проекции/viewport»** — опровергнута: проекция не негирует X
   (MRender.cpp:441), бэкенд не негирует X (MDisplaySDL2.cpp:4563-4568,
   glViewport — только Y-трансляция :4574), retail идентичен
   (RndrGL:37311-37328).
2. **«Двойное зеркало Y»** — опровергнута как причина X-симптома: Y
   компенсирован ровно один раз в проекции (k[1][1]<0) + GL y-up;
   glViewport/glScissor — трансляция, не флип контента; композит при
   uRot=0 тождественен.
3. **«Транспонирование при загрузке»** — опровергнута: transpose=GL_FALSE
   на row-major + `uMVP*v` ≡ `v·M` (GLES3_Shader.cpp:140; MMath.h:3955);
   PS3 делает то же через явный Transpose (MRenderPS3_Attrib.cpp:1079).
4. **«Зеркальная _CameraWMat из авторинга»** — опровергнута: цепочка
   yaw→матрица→Clear платформенно-нейтральна (§2.3); ввод по X нигде не
   негируется.

## 5. Патчи диагностики (внесены, env-gated, по умолчанию выключены)

1. **`RIDDICK_NO_CAMFLIP=1`** — пропуск негирования столбца 0.
   Якорь: `XREngine.cpp:1063-1075` (`CXR_ViewContextImpl::Clear`).
2. **`RIDDICK_DBG_MVP=N`** — дамп det(Model/Proj/MVP) первых N 3D-draw'ов
   + полные матрицы на первом. Маркер `[MVP]`. Якорь: `MDisplaySDL2.cpp`,
   `SetupCommonUniforms`, после `m_ModelMat.Multiply(m_ProjMat, MVP)`.
   Ожидание: `det(Proj) < 0` всегда; `det(Model) > 0` без костыля,
   `< 0` с костылём.
3. **`RIDDICK_DBG_SCISSOR=N`** — дамп первых N проекций боксов:
   `[SCISSOR]` (BSP2, WBSP2Portal.cpp:120-157, внутри `CalcBoxScissor`) и
   `[SCISSOR-TM]` (TriMesh, WTriMesh.cpp:1032-1048 + per-corner + явный
   лог early-out `z<0.1 -> FULL VIEWPORT`). Печатает: бокс в world,
   углы в view-space (x,y,z), экранные координаты ДО клампа, VPScale/
   VPMid/VPRect. Это решает, «узкие ли боксы на входе» или «ломается
   проекция».
